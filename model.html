Open Harness Model · referência inicial

Um método que você
pode abrir e entender.

Um harness descreve como agentes, conhecimento, checkpoints e decisões humanas se organizam. O OHM dá a essa descrição uma forma: um documento YAML 1.2 com extensão .ohm.

O que está dentro de um .ohm?

É um único documento de texto em UTF-8. Não é um ZIP, nem um modelo de linguagem. O modelo normalizado mantém seis propriedades principais:

schemaVersion
Identifica a versão da estrutura declarada pelo documento.
manifest
Identidade do harness: id, nome, versão, descrição, licença declarada e tags.
graph
Os participantes (nodes) e suas conexões (edges).
content
Conteúdo incorporado: prompts, agentes, skills, hooks, comandos e scripts.
runtime
Preferência de execução, CLI, variáveis de ambiente e referências de segredos. Credenciais não devem ser compartilhadas no arquivo.
validation
Metadados de validação, incluindo o perfil de simulação declarado.

Um primeiro arquivo.

Este exemplo apresenta a sintaxe YAML adotada sobre a estrutura 1.0.0. O grafo vazio demonstra o formato; o prompt multilinha exemplifica a autoria e não é executado. O leitor YAML do desktop ainda está em migração. O campo license é metadado do exemplo e não declara a licença do aplicativo.

hello.ohm
# OHM em YAML 1.2 — suporte no desktop em migração.
schemaVersion: "1.0.0"
manifest:
  id: hello
  name: Hello
  version: "0.1.0"
  description: Exemplo mínimo do Open Harness Model.
  license: MIT
  tags: []
graph:
  nodes: []
  edges: []
content:
  prompts:
    objetivo: |-
      Descreva o objetivo do trabalho.
      Defina as evidências para aceitar o resultado.
  agents: {}
  skills: {}
  hooks: {}
  commands: {}
  scripts: {}
runtime:
  preferred: api
  cli: null
  env: []
  secrets: []
validation:
  mockProfile: default

Estrutura válida é o primeiro passo.

O projeto possui um JSON Schema e um validador estrutural. JSON Schema continuará validando os dados depois da leitura do YAML: a sintaxe do arquivo e a estrutura do modelo são decisões distintas. O exemplo desta página foi verificado contra essa estrutura, após a leitura do YAML.

Passar nessa verificação não comprova a qualidade das instruções, disponibilidade de provedores, segurança de scripts ou equivalência de execução em outro ambiente.

Uma base concreta. Um modelo em evolução.

O OpenHarness já lê e exporta documentos JSON de harness, representa grafos e oferece validação estrutural e simulação. A decisão agora é adotar YAML para os arquivos .ohm, mantendo JSON nas APIs. A implementação do leitor e exportador YAML está pendente. A migração deverá preservar a leitura de arquivos JSON antigos, inclusive .oharness.

As conexões continuam usando IDs e arestas. Âncoras YAML não serão usadas para representar a topologia. Retornos e ciclos exigem regras de execução, limites e cancelamento; não são resolvidos pela troca da sintaxe.

A preservação integral de configurações na exportação, as regras de execução e o suporte por outras ferramentas ainda exigem desenvolvimento e verificação. Portabilidade é um compromisso de projeto; cada ambiente precisa implementar o modelo e declarar seus limites.

O OHM é uma proposta do OpenHarness. Esta página não anuncia padronização por terceiros, compatibilidade universal ou governança independente.

O manifesto apresenta os princípios que orientam essa evolução.
